# 产品定义

> 状态：当前有效（登记于 [README.md](README.md)）。修订本文件前必须经用户确认。

## 一句话定位

为 JRPG 服务、可复用的 3D 游戏引擎：把 JRPG 的领域概念（事件、对话演出、战斗规则、迷宫探索）做成一等公民，而不是通用引擎的插件补丁。

## 背景与要解决的问题

通用引擎（Unity/Godot/Unreal）对 JRPG 领域支持弱：事件脚本、回合制/QTE 战斗编排、立绘对话演出、迷宫与遇敌等概念都需要从零搭建，且风格化 UI 能力受限。自研引擎把这些领域语义内建，同时保持"可复用到多款 JRPG"的模块边界。

## 目标用户

1. 首要用户：项目所有者本人（用此引擎制作自己的 JRPG）。
2. 次要用户：未来复用此引擎的其他 JRPG 开发者（工作流：数据文件 + CLI 工具）。

## 目标游戏形态

参考《女神异闻录》系列的视觉形态：

| 维度 | 形态 |
|---|---|
| 场景 | 3D 城市街道 / 迷宫探索，第三人称或固定机位 |
| 角色 | 3D 角色模型；对话时以 2D 立绘 + 风格化文本框呈现 |
| UI | 高度风格化 2D UI：倾斜构图、大色块、shader 动效、缓动曲线——UI 本身是美术资产 |
| 演出 | cutscene 时间轴驱动：镜头运镜、字幕、BGM/SFX 同轨播放 |
| 战斗 | 规则可插拔：回合制状态机为首个实现；QTE 时间轴 / ACT 输入缓冲以预留合同承载 |
| 文本 | 中日英三语 i18n 表；CJK 禁则处理是一等公民 |

## 第一可玩闭环（Vertical Slice 定义）

玩家操控角色在测试迷宫中移动 → 触发遇敌进入一场**数据驱动的战斗**（含 QTE 时间轴钩子的最小演示）→ 胜利返回探索并获得道具 → 存档退出 → 读档后状态一致。

全程内容（地图、敌人数值、技能表、对话、演出）由数据文件组装，零硬编码剧情。

时点拆分（与 [02-milestones.md](02-milestones.md) 对齐）：

- **战斗闭环（P5 达成）**：上述流程去掉存档环节——移动→遇敌→战斗→胜利返回并获得道具。
- **完整第一可玩闭环（P7 达成）**：含版本化存档读档一致性的完整形态。

## 边界 @@BOUNDARY@@

### 做（主线）

- Persona 式视觉形态的引擎能力：3D 探索 + 风格化 UI + 立绘演出
- 可插拔战斗规则合同（见 docs/01-architecture.md §BattleRules）
- Windows(D3D12) + Linux(Vulkan) + macOS(Vulkan/MoltenVK)
- 数据先行工作流：JSON 数据文件 + schema 校验 CLI；GUI 编辑器远期另行立项

### 不做（非目标）

- 通用全类型引擎（FPS/开放世界/网络多人均不支持）
- 照片级写实渲染管线（PBR 材质仅作为 glTF 导入的兼容输入）
- 主机、移动端首发
- 第一阶段的 GUI 编辑器
- 主线内的 ACT 物理战斗实现（QTE 时间轴/输入缓冲以合同钩子承载；完整 ACT 战斗作为远期插件经 BattleRules 合同植入，见 [01-architecture.md](01-architecture.md) ADR-002）

### 已否定方向（防止回潮）

- 无。当前无被用户显式否定的历史路线；后续否定决策必须记录于此节。

## 成功标准（全部可验证）

1. **构建**：三个目标平台从源码一键构建并通过全部测试（CI 绿灯）。
2. **竖切**：30 分钟可玩 demo 达成上述第一可玩闭环，剧情内容零硬编码。
3. **可插拔验证**：在不修改引擎核心代码的前提下，替换一个最小战斗规则插件并通过其验收——证明 BattleRules 合同成立。
4. **渲染一致性**：同一套 RHI 合同测试在 D3D12 与 Vulkan 双后端绿灯。
5. **CJK**：日文禁则换行、中文排版用例通过 golden image 校验。
